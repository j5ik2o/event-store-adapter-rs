# ペルソナ定義 (personas)

計画Q&A（`user-stories-questions.md` Q1=B）により、ペルソナは1名に絞る。既存利用者の移行体験はストーリー化せず、要件（`../requirements-analysis/requirements.md` FR-6.2/FR-6.4）の直接検証で扱う。事業文脈は事業概要（`aidlc/spaces/default/codekb/sqlite/business-overview.md`）とチームプラクティス（`../practices-discovery/team-practices.md`）に基づく。

## ペルソナ: CLIツール開発者のケント

| 項目 | 内容 |
|---|---|
| 名前 | ケント（CLIツール開発者） |
| 役割 | Rust製CLIツールを開発する外部のOSS利用者（crates.io経由で本ライブラリを導入） |
| ゴール | (1) クラウドサービスに接続せず、単一ファイルのSQLiteでCQRS/イベントソーシングの永続化を実現する (2) 使わないバックエンドのクラウドSDK依存をビルドから排除して依存を軽く保つ (3) 既存のEventStore APIと同じ書き味でバックエンドだけ差し替える |
| ペインポイント | (1) 現状はDynamoDB/Bigtable前提でCLIツールにはクラウド依存が過剰 (2) 全バックエンドが無条件コンパイルされビルドが重い (3) ローカルテストに外部サービスやDockerが要る |
| 技術習熟度 | 高（Rust開発者。cargo feature・非同期ランタイムを日常的に扱う） |
| 利用頻度 | 開発期間中は毎日（アプリケーションの永続化層として常用） |

## ペルソナの優先順位

ケントが唯一の主役ペルソナ。全ストーリーはケントの視点で記述する。

## 関係者（ペルソナ化しない）

- **既存利用者**: 破壊的変更（デフォルトfeature廃止・エラー型変更）の影響を受けるが、計画Q&Aの決定によりストーリー化せず、README移行手順（FR-6.2）とCHANGELOG（FR-6.4）の要件充足で保護する。
- **メンテナ**: 意思決定者。CI・品質保証系の要件（FR-5）はメンテナの保守性関心だが、ストーリーとしてはケントへの品質保証（「壊れていないライブラリを使いたい」）として表現する。
