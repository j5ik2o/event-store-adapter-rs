# 監視設計 — u4-docs (monitoring-design)

U4（ドキュメント）の監視設計。本ユニットの成果物は静的文書とexamplesであり、実行時コンポーネントを持たないため、**ランタイム監視は適用対象なし**。文書の「鮮度」をどう保つかの整理のみを行う。

## ランタイム監視 — 適用対象なし

- U4はサービス・プロセス・パイプラインを追加しない（Q1=A確定）。SLO・メトリクス・アラートの設計対象が存在しない
- operation フェーズガードレールの「新サービスはヘルスメトリクス＋エラーレート」要件は、新サービスが存在しないため適用外

## 文書鮮度の維持（自動監視ではなく手順で担保）

| 乖離リスク | 検知手段（既存・変更なし） |
|---|---|
| READMEコード例と公開APIの乖離（TD-10の再発） | リリース前のレビュー（本ワークフローではU4コード生成のレビュー工程）。自動doctest/コンパイルチェックのCI追加はバックログ（examplesビルド検証と同枠） |
| DATABASE_SCHEMA.mdと実装DDLの乖離 | スキーマ変更はライブラリの自動作成コード（`event_store_for_sqlite.rs`）が正であり、文書は情報提供（project.md Mandated）。スキーマ変更を伴うPRのレビューで文書追随を確認 |
| CHANGELOGの記載漏れ | Conventional Commits運用（`lib-bump-version.yml` のsemver自動判定）が変更種別の一次記録。CHANGELOGはリリース時に突合 |

- 上記はいずれも**既存の運用の記録**であり、U4で新しい監視・チェックは追加しない
